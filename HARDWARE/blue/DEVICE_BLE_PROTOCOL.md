# 下层 BLE 设备协议（v1）

本文件定义下层采集/执行设备与 STM32 网关之间的 UART-BLE 透明传输协议。所有多字节整数均为小端序。

## 通用帧

`AA 55 | version(1) | type(1) | sequence(2) | payload_length(2) | payload(N) | CRC16-Modbus(2)`

- `version` 固定为 `0x01`。
- CRC 覆盖从 `version` 到 `payload` 的所有字节；初始值 `0xFFFF`，多项式 `0xA001`。
- 最大载荷为 128 字节；超长、版本错误或 CRC 错误的帧必须丢弃。
- 下层设备须在 UART 接收中断中缓存字节，并在任务/主循环中逐字节调用本协议的帧解析函数。

## 下行控制

类型为 `0x20`，载荷为 `control_id(1) + data(N)`。网关以 `sequence` 唯一标识一个执行请求；下层必须缓存最近一次控制帧的序号和结果。

重复的 `sequence`：不得再次驱动执行器，只重发此前的 ACK/NACK。

| 控制 ID | 数据 | 单位 / 范围 |
|---:|---|---|
| `0x01` | `int32` | 模式：0 自动，1 手动 |
| `0x02` | `int32` | 通风机速度，0–100 % |
| `0x03` | `int32` | 空调速度，0–100 % |
| `0x04` | `int32` | LED 亮度，0–100 % |
| `0x05` | `int32` | 内温上限，℃ ×100 |
| `0x06` | `int32` | 内温下限，℃ ×100 |
| `0x07` | `int32` | 温差，℃ ×100 |
| `0x08` | `int32` | 光照阈值，lx ×10 |
| `0x09` | 6 bytes | 年(0–99)、月、日、时、分、秒 |
| `0x0A` | 3 bytes | 开始时刻：时、分、秒 |
| `0x0B` | 3 bytes | 结束时刻：时、分、秒 |

下层应在控制生效（或明确失败）后立即回包：

`ACK (0x7E) / NACK (0x7F) | sequence=原控制序号 | payload=[0x20, result]`

`result=0` 成功；`1` 长度错误；`2` 参数非法；`3` 不支持；`4` 执行失败。网关等待 500 ms，最多发送 3 次。

## 上行数据

| 类型 | 含义 | 载荷 |
|---:|---|---|
| `0x01` | 心跳 | `device_status:uint8` |
| `0x10` | 遥测 | `tin_x100:int16, tout_x100:int16, lux_x10:uint32, battery_mv:uint16, device_status:uint8` |
| `0x11` | 告警 | `alarm_code:uint8` |

正常设备每 2 秒发送一次遥测；温度变化 ≥ 0.3℃、光照变化 ≥ 50 lx、状态变化或故障时应立即上报。告警后可每 2 秒重发，直到业务层确认或故障解除。

## 下层接入步骤

1. 将 `ble_frame.c/.h` 或等价帧编解码实现加入下层 MCU 工程。
2. 实现 UART 发送适配，将编码后的字节交给 BLE 模块发送。
3. 实现控制分发：校验控制 ID 与参数，写入阈值或驱动执行器，并返回结果码。
4. 在主循环/任务中周期发送遥测帧；故障时发送告警帧。
